状态定义：

- **已完成/实测**：代码已经落地，行数和验证结果可从提交与收据复算。
- **待实施/估算**：策略已确定，但代码尚未修改；行数只能给范围或明确不估。
- **延期**：当前明确不动，避免触碰尚未稳定的摘要合同。

- 兼容边界：所有原包装器名称、返回值和调用入口保留；紧凑 canonical JSON、漂亮排序 JSON、JSONL、指针换行、CRLF/BOM、追加写入和 create-if-absent 合同没有合并。

父目录同步策略保持原义：普通文件写入为 `NONE`，Environment Rule/Skill/Binding 为 `BEST_EFFORT`，macOS 安装事务为 `REQUIRED`；Rule rollback bytes 继续在替换前应用 `0600`。`platform_transaction.atomic_write_canonical_json()` 继续返回精确 canonical payload bytes，其余既有包装器继续返回 `None`。

## 10. R4 Exchange Mechanism

- 状态：**已完成候选实现/定向验证通过**
- 唯一机制 Owner：`scripts/memory_exchange_contract.py`
- 显式传输边界：四个公开 Manager 继续作为各自流的门面，并以 `ExchangeStreamFacade.exchange_port()` 向 `CloudFolderTransport` 提供固定的 `ExchangeStreamPort`；Cloud transport 不再通过 `hasattr` / `getattr` 推断交换能力。
- 迁移顺序：project attachment -> project evidence -> archive federation -> Environment。
- 共享范围：仅游标与前任声明验证、受限 JSONL 分页、manifest 身份构造/验证、payload 大小与哈希验证、认证绑定验证、严格连续链与 Environment 重叠窗口分类。

R4 明确保留四条独立失败域。`archive-v1` 继续没有 `stream_id` 字段并保留协议 v1/v2 读取、未认证导入和 `no-change` 重放；`environment-v1` 继续拥有 staging、事务、receipt、重叠恢复和认证导入；project evidence 与 project attachment 继续拥有各自的 payload codec、路径、event ledger、replica state、replay 拒绝、对象/manifest 校验和独立锁。四者的 ACK、cursor、账本、ZIP 写法、异常文本与持久格式均未合并。
